# Передача проекта новому разработчику

Короткая инструкция: что прочитать и что сделать, чтобы за два часа начать
вносить изменения в проект.

## 1. Что изучить по порядку

| Шаг | Что открыть | Зачем |
|---|---|---|
| 1 | `README.md` | Состав проекта, команды запуска и сборки |
| 2 | `docs/_build/html/overview.html` | Что делает приложение и для кого |
| 3 | `docs/_build/html/architecture.html` | Слои, модули и правило их разделения |
| 4 | `docs/_build/html/api.html` | Публичный интерфейс модулей |
| 5 | `docs/_build/html/developer_manual.html` | Окружение, тесты, сборка, соглашения |
| 6 | `docs/ISSUES.md` и `CHANGELOG.md` | Что уже сделано и что запланировано |

## 2. Подготовка окружения

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m pip install pytest pytest-cov flake8 psutil pyinstaller sphinx
```

Проверка, что окружение собрано верно:

```bash
python -m app.main        # должно открыться окно
pytest -q                 # ожидается: 143 passed
flake8 app tests          # ожидается: ни одного замечания
```

Если тесты проходят, а линтер молчит — окружение готово.

## 3. Ключевые точки кода

| Что менять | Где смотреть |
|---|---|
| Формат, размер, водяной знак, EXIF | `app/processor.py`, класс `ImageProcessor` |
| Схема базы и запросы | `app/database.py`, класс `DatabaseManager` |
| Фоновая обработка и отмена | `app/worker.py`, класс `ProcessingWorker` |
| Окно, кнопки, очередь, предпросмотр | `app/ui.py`, класс `MainWindow` |
| Модели данных | `app/models.py`, `Preset` и `QueueItem` |
| Сборка `.exe` | `ImageBatchStudio.spec` и `build_windows.bat` |

## 4. Три правила, которые нельзя нарушать

1. **Бизнес-логика не импортирует интерфейс.** `processor.py` не должен
   знать про `tkinter` и `app/ui.py`. Иначе пропадёт возможность тестировать
   обработку без окна.
2. **SQL собирается только через параметры `?`.** Конкатенация строк
   запрещена. Следит тест `tests/test_security.py`.
3. **Ошибка одного файла не прерывает очередь.** Исключение внутри цикла
   перехватывается, элемент получает статус «Ошибка».

## 5. Как вносить изменения

1. Создать задачу в `docs/ISSUES.md` с приоритетом.
2. Внести изменения в одном модуле.
3. Добавить или исправить тест, который падал бы до изменения.
4. Прогнать `flake8 app tests` и `pytest -q`.
5. Дописать запись в `CHANGELOG.md`.
6. Если изменился публичный интерфейс — обновить docstring в формате
   Google Style и пересобрать документацию:
   `sphinx-build -b html docs/source docs/_build/html`.

## 6. Пересборка артефактов

```bash
build_windows.bat              # .exe, автоматически с проверками
python tools/screenshot_ui.py  # снимки состояний окна
python tools/check_exe.py      # проверка собранного файла
python tools/make_report.py    # отчёт по практике
```

## 7. Куда обращаться

* Сборка и тесты не проходят — сначала читать сообщение pytest:
  в нём указан конкретный тест и причина.
* Непонятно, зачем существует модуль — смотреть `docs/_build/html/api.html`,
  там описание каждого класса и метода.
* Нужна новая функция — сначала запись в `docs/source/backlog.rst`,
  затем реализация и тест.
